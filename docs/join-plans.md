# Cross-table reference join plans

`csv join preview` resolves explicitly declared external keys across selected CSV
sources before import. Native item identities are generated by the pm SDK and
saved in the review artifact. Core owns item identity, lifecycle, parent and
`blocked_by` validation; provider adapters continue to own their remote keys.

```sh
pm csv join preview joins.json --output reviewed.json --json
pm csv join apply reviewed.json --json
# Retrying the SAME reviewed artifact rechecks current target revisions.
pm csv join apply reviewed.json
```

Example input (`joins.json`):

```json
{
  "version": 1,
  "tables": [
    {
      "name": "projects", "key": "key",
      "csv": "key,title\np1,Launch\n",
      "fields": {"title": "title"}, "references": []
    },
    {
      "name": "tasks", "key": "key",
      "csv": "key,title,project\nt1,Build,p1\n",
      "fields": {"title": "title"},
      "references": [{"column": "project", "table": "projects", "kind": "parent"}]
    },
    {
      "name": "checks", "key": "key",
      "csv": "key,title,task\nc1,Verify,t1\n",
      "fields": {"title": "title"},
      "references": [{"column": "task", "table": "tasks", "kind": "blocked_by"}]
    }
  ]
}
```

The SDK exports `previewJoins(pmRoot, input)` and
`applyJoins(pmRoot, plan, {author})` from `pm-csv` (and the corresponding typed
`JoinInput`, `JoinPlan`, `JoinReceipt`, `JoinIssue` declarations). Preview returns
`{receipt, plan?}`. Only successful previews produce a plan. Preview never writes
tracker state. CLI output uses the host's compact TOON or `--json` rendering;
full source-bearing artifacts are saved only with `--output`, exclusively with
private file permissions. Treat review artifacts as source data.

Mapping names are exact SDK create-option names: `title`, `body`, `type`,
`status`, `priority`, `tags`, `assignee`, `sprint`, `release`, `estimatedMinutes`,
`acceptanceCriteria`, `closeReason`, `completedAt`. Every mapped header must
exist. Other headers have no effect. `title` is required. The SDK performs native
normalization; body whitespace is passed intact to it. Types and statuses must
be configured native IDs; terminal status meaning comes from SDK registry roles
and requires `closeReason`. Priority is an integer 0–4; estimates are finite
0–1,000,000,000 minutes. Lifecycle policy remains enforced by native SDK create.

The version 1 boundary is strict: unknown properties, sparse arrays and wrong
primitive types are rejected. Limits: 16 tables, 16 reference declarations per
table, 128 columns, 1,000 selected rows total, 8 MiB total UTF-8 CSV. Comma CSV
accepts quoted cells, BOM, consistent LF or CRLF. Keys compare case-sensitively
after trimming surrounding whitespace. Empty keys, duplicates (including unused
ones), unresolved nonempty reference cells and cycles block the entire preview.
An empty reference cell means no edge. Each declaration contains one key per
cell; use multiple declared dependency columns for multiple edges. Coordinates
are one-based logical CSV records and columns, with the header as record 1;
embedded newlines do not add logical records.

Plans bind exact SHA-256 source-byte digests, tracker settings, generated native
IDs and explicit `expected: "absent"` target revisions. Sources are captured inline, so
apply never rereads external files. Any source or artifact edit invalidates the
review. A new preview assigns new identities and represents a new import; use
the original artifact for retry. This is a create-only import, with no keyed
update, export or sync protocol. Existing CSV import/export, spreadsheet checkout
and row-lineage workflows remain separate APIs.

Apply uses `commitWorkspaceTransaction` and native SDK create. Every retry reads
current target documents and immutable history, including after a committed
journal. An unchanged target must still have the exact owned create revision;
later edits refuse replay. Foreign collisions are skipped with `foreign`, and
all dependent targets with `dependency_skipped`, without changing those records.
No separate checkpoint, outbox or custom lease files are introduced. Native SDK
item locks and transaction writer locks own concurrency. As with existing CSV
atomic import, host persistence fencing beyond item-lease expiry remains a
host SDK requirement (tracked separately).

This operation does not delete or close created records on failure. If a later
native create fails, earlier creates and their immutable history remain and the
SDK journal records the reconciliation requirement. Inspect current targets and
the journal before retrying; never claim that an unsuccessful import rolled back
all creates. Crash interruptions can resume the same reviewed plan when all owned
revisions are unchanged. If an owned target changed, reconcile and preview again.

Receipts contain bounded counts and at most 20 coordinate-only issues;
`issueCount` reports the complete total. `ok: false` means no reviewable plan or
some targets skipped. Applied/unchanged/skipped partition the selected rows.
Thrown `JoinRefusal` errors have exit status 2, `code`, `remedy` and host-native
`nextSteps`: `csv_join_invalid`, `csv_join_io`, `csv_join_settings_changed`,
`csv_join_target_changed`, `csv_join_apply_failed`, `csv_join_reconcile`.
Correct the input or reconcile current SDK state as directed; retries never
silently overwrite newer target revisions.

## Without git

Preview, apply and replay work in plain initialized trackers without a Git
executable. Git is not needed for these commands.

## Explicit scope and refusal boundaries

All package mutation paths share `buildMutationIntent` in `mutation-intent.ts`.
A create with no parent uses the SDK's `unset: ["parent"]` form; an empty CSV
parent cell never means “inherit the current focus”. Absent create assignment,
reviewer, sprint/release, goal/objective and blocker fields are also explicitly
unset, and absent dependency/file/doc/test collections are explicitly cleared.
The intent never reads session focus or the working directory. Native `none`/`null`
clear aliases for every supported nullable scope scalar and linked collection are converted to explicit unsets too.
Stored SDK patch/restore snapshots preserve their literal values and do not
interpret them as command-input aliases.

Legacy CSV imports use the same builder for standard, streaming, atomic and
schema-negotiated imports. On keyed updates, absent columns and empty cells
preserve current values and dependency edges. Nonempty supported cells set values;
`none`/`null` explicitly clear supported nullable scope fields, and blocker cells add edges.
Spreadsheet patches, compensation and marker cleanup preserve unselected native
scope; raw patches/restores build their selected scope from the current document
inside the SDK item lock. Native lifecycle policy still owns terminal transitions.

Join replay compares current native scope to the reviewed source intent using
SDK canonicalization. It refuses old owned records with an inherited parent,
unreviewed scope or extra links, including when their unchanged history and a
committed journal would otherwise look reusable. Lineage reports these old
scope mismatches as identity conflicts; legacy atomic create receipts also refuse
scope drift. Changing focus after preview is harmless for a correctly reviewed
plan and never adds a parent.

Both `previewJoins` and `applyJoins` expose only `JoinRefusal` on failure. Malformed
quoting, ragged records and inconsistent line endings are wrapped from the table
parser, retaining its `sourceCode`, actionable `remedy` and original `cause`.
The CLI does the same for invalid UTF-8/JSON and file errors. Expected lower-level
failures are not leaked as another API's refusal family.
